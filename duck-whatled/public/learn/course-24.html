第 24 课 · 迁移地图:这只鸭子教会你的五件事

这一课解决什么问题:课程开头承诺过"最后把学到的东西迁移到其他领域"。这一课把 30 天里反复用过的五个方法摆成一张地图,每条都按"鸭子里的做法 → 迁到哪 → 你的第一步"给出落点。

前置:至少学过 第 05 课;学过的课越多,这张地图对你越值钱。

1. 一张地图

 强化学习试错法 ────────┬─▶ 游戏 AI / 推荐系统
                        └─▶ 任何可模拟的决策问题
 总线通信与嵌入式 ────────▶ IoT / 智能家居 / 设备互联
 CAD + 3D 打印 + 测试片 ──▶ 产品原型 / 创客项目
 预注册 A/B + 实验记录 ───▶ 任何领域的调参 / 运营实验
 sim2real + 域随机化 ─────▶ 数字孪生 / 自动驾驶仿真

判断一个问题能不能用鸭子的方法,只看一个特征:它有没有"可以反复尝试、结果可观测"的闭环。鸭子有(摔倒→爬起→再来),游戏有(输→复盘→再来),推荐系统有(推送→点击率→调整)。

2. 五条迁移路线

路线一:强化学习试错法 → 游戏 AI / 推荐系统

  • 鸭子里的做法:不逐帧写动作,定好奖励让策略自己试——第 05 课冒烟测试先验证链路,第 06 课看曲线判断练没练成。
  • 迁到哪:游戏 AI、推荐系统、定价、排班——任何"能写清楚什么算好"的决策问题。
  • 你的第一步:找一个免费模拟环境,先跑一次自己的"5 次迭代冒烟测试":证明链路通,再谈效果好。

路线二:总线通信与嵌入式 → IoT / 智能家居

  • 鸭子里的做法:15 个舵机挂在同一条 1 Mbps 总线上,靠 ID 通信而不是一人一根线(第 10 课);小芯片专职把实时控制做稳(第 11 课)。
  • 迁到哪:智能家居、传感器网络、设备互联——本质都是"一条总线 + 一套协议 + 实时控制"。
  • 你的第一步:用树莓派或 ESP32,让两个设备经串口或 MQTT 互发一条带 ID 的消息,只回应叫到自己 ID 的指令。

路线三:CAD + 3D 打印 + 测试片先行 → 产品原型 / 创客项目

  • 鸭子里的做法:换打印机、换材料都不直接打正式零件,先打测试片、量出公差、回填模型(第 09 课)。
  • 迁到哪:任何"想法 → 实物"的路:外壳、支架、创客作品、小批量产品。
  • 你的第一步:下一个打印件之前,先打一个 2 厘米测试片,量出误差再改模型——几分钟的成本,省下整件重打。

路线四:预注册 A/B 与实验记录 → 任何技术领域的调参与运营实验

  • 鸭子里的做法:改参数前先注册假设,一次只改一个变量,结论只认证据(第 14 课);证据落进实验总表,不许靠回忆(第 28 课)。
  • 迁到哪:网站改版、文章标题、训练超参、运营方案——只要能对比,就适用。
  • 你的第一步:下次想"优化点什么"时,先写一句"如果我改变__,那么__应该变化,因为__",跑完再补结论,顺序不许反。

路线五:sim2real 与域随机化 → 数字孪生 / 自动驾驶仿真

  • 鸭子里的做法:仿真会骗你,所以训练时故意把世界调"坏"——摩擦、质量、延迟都随机化,让策略学会抗干扰(第 15 课,expD/expE 的教训)。
  • 迁到哪:数字孪生(工厂/建筑的仿真镜像)、自动驾驶仿真——凡是"仿真里得出、现实里兑现"的结论。
  • 你的第一步:给自己的模拟加一种"世界不乖"的扰动,看结论还成不成立——不成立的部分,就是仿真在骗你的地方。

3. 一个共同底层

五条路线是同一个闭环的五个化身(第 01 课画过):提出目标 → 尝试 → 观测 → 修正再试。鸭子身上它叫强化学习,硬件上叫调试,产品上叫迭代。你带走的不是鸭子,是这个闭环。

动手练习(15 分钟)

挑一条最想走的路线,写一张 200 字"迁移卡":鸭子里的原方法(标课程号)、你领域里对应的问题、你的第一步、怎么判断第一步成功。第 26 课选毕业设计时会用到它。
