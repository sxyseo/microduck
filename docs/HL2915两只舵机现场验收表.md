## 0.5 Windows 调试器和串口确认

第一次插入半双工 USB 调试器时，先不要给舵机上电：

1. 打开“设备管理器”→“端口（COM 和 LPT）”，记录新出现的 `USB Serial Port (COMx)`；
2. 如果出现黄色感叹号，先安装调试器厂家提供的 USB 串口驱动，再拔插一次；
3. 插拔前后各执行一次下面的命令，只有新增的端口才是本次调试器候选端口：

```powershell
Get-CimInstance Win32_SerialPort |
  Format-Table DeviceID,Caption,Description -AutoSize
```

4. 关闭串口监视器、Arduino IDE、串口助手和其他可能占用该端口的程序；
5. 把后续命令中的 `COM3` 替换为实际 `COMx`，不要根据电脑上已有的 `COM1` 猜测。

调试器能出现在设备管理器，只证明 USB 驱动和电脑连接正常，**不证明舵机已接通**。舵机是否正常，
必须以下面的单只 Ping 命令得到 `响应=[1]` 才能确认。

如果还没有调试器，购买页至少要明确写出下面四件事；只写“USB 转 TTL”而没有“半双工总线舵机”
字样的板子不要先买：

- 支持**单线半双工 TTL**，能在发送和接收之间自动切换方向；
- 支持 1 Mbps（最好明确支持 Feetech/SCS/STS/HLS 协议）；
- 舵机 Vcc 使用独立的 9–14 V 电源，调试器只负责数据和共地；
- 调试器的 Signal 电平与 HL-2915 兼容，且不会把 12 V 反送进 USB 口。

飞特官方把 `FE-URT-1 / FE-URT1-C001` 列为 USB 转 TTL/485 总线编程器；可从[官方调试板页面](https://www.feetech.cn/serial-port-series-steering-gear_50681.html)
进入资料。购买第三方替代品时，必须让卖家书面确认“TTL 单线半双工 + 自动方向切换 + 1 Mbps”，普通 USB-UART/CH340 板不能默认满足。

第一次接线只保留三条电气关系：`电源 GND ↔ 舵机 GND ↔ 调试器 GND`、
`电源 +12 V → 舵机 Vcc`、`调试器 DATA ↔ 舵机 Signal`。调试器上的 Vcc 针脚除非说明书明确
写着可承受并输出舵机电压，否则留空；**不要把 12 V 插入 USB 转接器的 5 V/3.3 V 针脚**。

如果已经在仓库根目录执行过 `cargo +1.89.0 build --release -p duck-control --bins`，
现场优先使用 `target\release\hl2915_probe.exe`、`hl2915_record.exe` 等已编译程序；
下面的 `cargo run` 是没有 Release 二进制时的等价备用写法。

## 2. 舵机 A：保持出厂 ID=1

只接 A，执行：

```powershell
.\target\release\hl2915_probe.exe COM3 1
# 没有 Release 二进制时：
# cargo +1.89.0 run -p duck-control --bin hl2915_probe -- COM3 1
```

预期：输出 `请求 ID=[1]；响应=[1]`，并看到位置、电压、温度。

```powershell
New-Item -ItemType Directory -Force artifacts | Out-Null

  --json-out artifacts\servo-a-id1-validation.json
```

## 3. 舵机 B：从 ID=1 改为 ID=2

断电、拔掉 A，只接 B。先确认 B 还是 ID=1：

```powershell
.\target\release\hl2915_probe.exe COM3 1
```

确认无误后写入新 ID：

```powershell
.\target\release\hl2915_probe.exe COM3 1 --set-id 2
```

## 8. 现场结论

只有以下项目全部满足，才可以进入 Radxa 和结构安装：

- [ ] 两只 ID 唯一；
- [ ] 60 秒只读 `errors=0`；
- [ ] 600 秒 CSV 有效；
- [ ] 电压、温度、电流已记录；
- [ ] 没有机械件时空载回中正常；
- [ ] 若接入 IMU，混合协议 `imu_ready=true`；
- [ ] 所有日志、照片和 CSV 已保存到同一实验目录。
