## 1. 全局架构：这只鸭子最后长什么样

```text
 ┌──────────── 电力流 ────────────┐   ┌──────────── 数据流 ────────────┐
 │                                │   │                                │
 │ 3S 电池 (9.9–12.6V)            │   │ Radxa Zero 3W (主控)           │
 │   ├─ 保险丝 + 急停开关          │   │   ├─ UART ←→ 飞特转接板 ←→ 15× │
 │   ├────────→ 15× HL-2915 母线  │   │   │            (半双工TTL 1M)  │   HL-2915 舵机总线
 │   └─ UBEC 12V→5V ──→ Radxa     │   │   ├─ I2C  ←→ LSM6DSV16X IMU    │
 │                                │   │   └─ MIPI ←→ IMX219 摄像头     │
 └────────────────────────────────┘   └────────────────────────────────┘
 策略：ONNX 61 维观测 → 14 维动作，50Hz，跑在 Radxa 上（robotd）
```

**与官方方案（Dynamixel XL330 + Robot HAT）的差异，只有四层**：

| 层 | 官方 | 本路线 | 影响 |
|---|---|---|---|
| 舵机 | 15× XL330（3.7–6V） | 15× HL-2915（9–14V） | 电压、辨识参数、策略全换 |
| 总线协议 | Dynamixel V2（FF FF FD 00 + CRC16） | 飞特磁编码（FF FF + ~sum） | 只换 `duck-control` 总线层 |
| IMU | imu_to_dxl 板挂总线 ID 200 | I²C 直连主控 | 少一块自绘板，少一个故障点 |
| 配电 | 官方 HAT（4 层板） | 转接板 + UBEC | 失去板载音频，其余等价 |

**一条铁律**：策略网络的观测是 **61 维**（姿态 3 + 重力 3 + 关节位置 14 + 关节速度 14 +
上次动作 14 + 指令 13）、动作 **14 维**（嘴不算）、控制 **50Hz**。
改动可以无限多，但这三样不能变——变了就得连训练代码一起改，那是一条长得多的路。

## 2. 阶段 A：台架（对应 HL2915-002）

具体命令和原理在 [新手学习文档 §12](新手学习文档.md)，这里只列骨架：

```bash
cd microduck-replica/rl-series/scripts
python3 hl2915_bench.py list              # 找串口
python3 hl2915_bench.py 1                 # 体检：PING+寄存器快照
python3 hl2915_bench.py 2 --seconds 60    # 遥测流
python3 hl2915_bench.py 3                 # 闭环小步幅
python3 hl2915_bench.py 4 --minutes 10    # 10 分钟拷机 → PASS
python3 hl2915_bench.py 5 --ids 1,2       # 双舵机 SYNC_READ/WRITE（真机控制环的形状）
python3 hl2915_bench.py 6 --kp 800 --kd 80 # 阶跃录制：50Hz 曲线→CSV+超调/稳态误差/整定指标（辨识 kp/kd）
python3 hl2915_bench.py set-id --new-id N # 分配关节 ID（一次只接一只）
```

**验收**：两只舵机各自过课 1–4；课 5 两只同步反向摆动、读数误差 ≤4 步。

### 顺手为阶段 F 攒辨识数据（做完拍照片/填表，重训时要交）

| 要辨识的量 | 怎么测 | 填到哪（阶段 F） |
|---|---|---|
| 位置环 kp/kd | 课 6 改 21/22 号做阶跃，自动录 CSV 并算超调/稳态误差/整定（扫几组 P/D 择优） | `microduck_constants.py` |
| 堵转力矩 | 已知力臂挂砝码，读到过载保护触发为止 | `friction_dr_bam.py` 的 forcerange |

## 3. 阶段 B：IMU 接入

**为什么必须有**：61 维观测里有 6 维来自 IMU（机体角速度 3 + 重力投影 3），
而且**摔倒检测就靠重力向量**。没有 IMU，策略等于闭眼走路。

### 3.1 选哪条路

| 路线 | 做法 | 建议 |
|---|---|---|
| **I²C 模块直连（推荐）** | LSM6DSV16X 模块 4 根线接 Radxa 40-pin I²C | 少一块自绘板、少一个总线故障点；原型机当年就是 BNO055 走 I²C |
| imu_to_dxl 自绘板挂总线 | 板子固件本来就备了飞特协议分支 | 等整机走通、想还原官方架构时再上 |

### 3.2 接线（断电操作）

LSM6DSV16X 模块 → Radxa 40-pin：`VCC→3.3V`、`GND→GND`、`SDA→SDA`、`SCL→SCL`
（40-pin 上具体哪两个脚是 I²C，查 Radxa 文档；接好后 `i2cdetect -y <总线号>`
扫到 **0x6A**（或 0x6B）就是接对了）。

**安装朝向是硬约束**：软件里传感器→躯干的安装旋转写死为
`trunk = [+raw_z, +raw_y, −raw_x]`（`duck-control/src/imu.rs` 的 `DEFAULT_MOUNT`，
训练也是按这个朝向做的）。模块贴装时让芯片的 +Z 指向鸭子头顶、+Y 指向前方；
做不到就改代码里的 mount，但**改完必须和重训时的朝向一致**，并在构建日志里记录。

### 3.3 软件约定（阶段 E 写 `Feetech2915Io` 时一并实现）

IMU 读取要产出和官方完全相同的结构（`duck-control/src/imu.rs::ImuData`）：

- `gyro[3]`：机体角速度，rad/s（LSM6DSV16X 量程 ±500dps 时 17.5 mdps/LSB）；
- `gravity[3]`：投影重力单位向量，**正立时 = [0, 0, −1]**（策略观测 + 摔倒判定的那个数）；
- `quat[4]`：标量在前 [w,x,y,z]，用芯片 SFLP 硬融合输出，别自己写融合。

### 3.4 五步验证法 + 验收

1. **静置零漂**：平放 30 秒，`gyro` 每轴绝对值 < 0.05 rad/s；
2. **翻转重力**：正立 `[0,0,−1]` → 倒立 `[0,0,+1]`，z 变号、模长始终 ≈1；
3. **方向检查**：鸭子低头 → gyro 的 Y 轴符号与训练约定一致（不对就改 mount，别改符号表）；
4. **四元数连续**：慢转 90°，无跳变、模长 ≈1；
5. **读取稳定**：以 50Hz 连读 10 分钟，"与上次完全相同"的 stale 读连续不超过 3 帧。

全过 → 阶段 B 验收 ✅。任何一步不过，先查接线再查地址，**不要**靠"软件里乘个 −1"糊弄过去。

## 4. 阶段 C：摄像头（cam）

**不用写驱动**——官方软件栈已经写好：`mediad` 负责出 720p30 流，
`duck-detect` 负责在帧上跑检测（Radxa 上走 NPU/RKNN）。你要做的是把硬件装对、验证链路。

1. **装**：IMX219（Pi Cam v2）FPC 排线接主控 MIPI CSI 座。排线 **4–15cm 足够**
   （主控和摄像头同在头部，不过脖子）；壳内装配时摄像头**转 90°**
   （官方就是横着的，这是逆向出来的结论，不是错误）。
2. **在 Radxa 上验**（Mac 没有 MIPI，别在 Mac 上浪费时间）：

```bash
v4l2-ctl --list-devices                                   # 认出 /dev/video*
v4l2-ctl -d /dev/video0 --stream-mmap --stream-count=3    # 连续出 3 帧不报错
robotctl health                                           # mediad 起来后应全绿
duckctl open                                              # 笔记本开控制台 :8080 看画面
```

**验收**：v4l2 出图 ✔ → 控制台看到流畅 720p30 画面 ✔ → 画面方向正确
（横置 90° 的补偿已生效）✔ → `duck-detect` 检测框画在你放的目标上 ✔。

## 5. 阶段 D：供电与主控（官方 HAT 在飞特路线上的替代）

官方 HAT 干四件事：舵机总线半双工缓冲、配电、音频、传感器座。飞特路线逐项替代：

| HAT 功能 | 飞特路线替代 | 说明 |
|---|---|---|
| 半双工 TTL 舵机总线 | **¥22 飞特转接板**（ST/SC 系列通用） | Radxa UART → 转接板 → 舵机总线 |
| 12V→5V 配电 | **UBEC（≥3A）** | 给 Radxa 40-pin 5V 供电 |
| 音频（codec+功放） | **先放弃** | 整机走通后想加再补独立小功放板 |
| Qwiic 传感器座 | 直接用 40-pin I²C | IMU 就接这里 |

### 5.1 电池：选 3S

HL-2915 工作窗 9–14V。**3S 锂电（满 12.6V、空 ~9.9V）正好全程落在窗内**；
官方的 2S（6.6–8.2V）带不动 HL，这是换舵机路线最刚性的约束。

### 5.2 电力拓扑（全部断电接线，接完用万用表蜂鸣档复查）

```text
3S 电池 ── 保险丝(台架 5A；总装后按实测走路峰值电流的 1.5 倍换，见验收) ── 急停开关 ──┬── 舵机总线（转接板电源端子）
                                        └── UBEC 12V→5V ── Radxa 5V/GND
所有 GND 共地（电池、转接板、UBEC、Radxa、IMU）
```

**验收**：
- 空载母线 12.3–12.6V；
- 单舵机课 3 动作时母线压降 < 0.5V（超过说明电源内阻大，先换电源）；
- 急停按下 → 所有舵机立刻失力；再上电 → 舵机**保持无力**（扭矩默认 0，要软件才打开）；
- UBEC 输出 5.0–5.2V，Radxa 稳定开机 10 分钟。

## 6. 阶段 E：软件适配（写 `Feetech2915Io`）

### 6.1 代码地图（改哪些文件）

| 文件 | 现状 | 要改成 |
|---|---|---|
| `duck-control/src/bus.rs` | rustypot `Xl330Controller`，读块 124/12，慢速 144/3 | 新增 `Feetech2915Io`：飞特帧层，读块 **56 起 14 字节**（遥测一次拿全），写目标 42（+46 限速） |
| `duck-control/src/io.rs` | `RobotIo` trait（read/write/set_gain/set_torque/slow_sensors） | **不动**——这是整条接缝 |
| `duck-control/src/imu.rs` | 从总线 12 字节块解码 | 换成 I²C 读 LSM6DSV16X，`ImuData` 结构和朝向不变 |
| `duck-control/src/model.rs` | 电池窗 6.6–8.2V、ID 表 | 电压窗改 9–14V（62 号遥测 0.1V 直接除 10）；ID 表沿用 10–14/20–24/30–34 |
| `robotd/src/main.rs` | `DynamixelIo::open` | 按配置选 `Feetech2915Io` |
| 策略清单 | `robot.servos="xl330"`, `hw_rev=1` | 改成 `"hl2915"` / `2`（清单校验只强制 obs 61/action 14/型号，这两个是显示+门控字段） |

帧格式、指令码、寄存器表全部在 [新手学习文档 §12.3](新手学习文档.md)，
帧收发参考实现就是台架脚本 `hl2915_bench.py`（已对协议手册示例逐字节验证）。

### 6.2 步骤（每步可回退）

1. **建模块**：`duck-control` 里新增 `feetech.rs`，把 `hl2915_bench.py` 的
   packet/parse/transact 翻译成 Rust（`serialport` crate 开 1Mbps 8N1）；
2. **单测**：用手册的示例帧当测试向量（PING/READ/WRITE/SYNC 各一条），`cargo test` 过；
3. **双舵机真总线**：`Feetech2915Io` 只接 2 只舵机跑 `read/write/set_torque`，
   50Hz 跑 10 分钟零 `ShortRead`；
4. **HOME 缓动**：实现 `robotd init` 同款的插值到 `DEFAULT_POSITION`——
   2 只舵机插在对应关节索引上，从当前位缓动到 home，过程平滑无抽动；
5. **接 IMU**：I²C 路径接进 `read()`，`ImuData` 三项过阶段 B 的五步验证。

### 6.3 验收

- `cargo test` 全绿（含新的帧层向量测试）；
- 台架 2 舵机 + IMU：50Hz 控制环跑 10 分钟，丢读 0；
- `set_torque(false)` 立刻失力、`set_torque(true)` 恢复；
- 断一只舵机的线 → 得到明确的 `ShortRead` 报错而不是静默用旧值。

## 8. 阶段 G：整机装配、部署、测试金字塔

1. **装机**：15 只舵机（阶段 A 已分好 ID、贴好标签）+ 阶段 D 的电控 + 3S 电池。
   每只装完先手掰全行程听有没有碰壳。
2. **上电第一次**：只接总线不装腿（或吊装），`robotctl health` → `robotctl monitor`
   确认 16 个读块（15 舵机 + 各自遥测）全回。
3. **部署策略**（详见 [进阶学习文档 §3](进阶学习文档-训练仿真与部署.md)）：

```bash
scp alpha_walking.onnx radxa@<IP>:/home/radxa/
sudo robotctl policy load walk /home/radxa/alpha_walking.onnx
robotctl policy list
```

4. **测试金字塔**（一层过了才准上一层，**第一次上电必须手扶**）：

| 层 | 环境 | 通过标准 |
|---|---|---|
| L5 吊装 | 悬空跑策略 | 14 关节按策略运动、无超温、电流正常 |
| L6 软垫 | 低重心、软垫、手扶 | 站立稳定、可从坐姿站起 |
| L7 平地 | 开阔平地、低重心 | 直线走 ≥2m、可停止可急停、连续 3 次成功 |

**验收留档**：每层的视频、电流/温度曲线、失败回放，全部进 `构建日志.md`——
这是整个复刻项目最值钱的资产。

## 9. 降本路线：这一路攒下了什么，下一只舵机怎么换

### 9.1 哪些投入是一次性的

阶段 A–G 走完后，**转接板、教程、`hl2915_bench.py`、`Feetech2915Io`、辨识方法、
部署流水线全部复用**。换一只更便宜的飞特磁编码舵机，边际成本只有三件事：

| 要动的 | 工作量 |
|---|---|
| 电压窗与保护寄存器（14/15/28 号） | 一条写指令 |
| 寄存器差异（以**那只舵机的内存表**为准，如经典 STS 系列目标位置地址不同） | 改两个常量 + 重跑课 1–5 |
| 辨识五参数重测 + 重训 | 阶段 A 的表 + 阶段 F 一轮 |

### 9.2 候选与选型规则

| 型号 | 电压 | 重量 | 定位 |
|---|---|---|---|
| HL-2915-C001（本教程） | 9–14V | 27.8g | 跑通全链路的开发单元 |
| HD-1910-C001（飞特"小鸭舵机"） | 4–8.4V | 21g | 复刻装机候选（2S 母线友好）；⚠️ 脚序与 HL 相反：1=Signal / 2=Vcc / 3=GND |
| STS3215 系列通用货 | 4.8–7.4V（型号而定） | ~21g | 最便宜的协议同族货，量大管饱（lerobot 生态同款） |

**规则**：整机验收前不要囤货。先用 2 只开发舵机把 F 走通，G 阶段按
"单只价格 × 15 + 辨识偏差风险"决定量产型号；同一批货**全部同型号同固件批次**，
混批是最隐蔽的坑。

### 9.3 成本锚点

官方整机 $399（XL330 路线）。本路线的大头节省在舵机与主控板
（官方 HAT 打样几百元起 → 转接板 ¥22 + UBEC）；总账用
[复刻总清单](../microduck-replica/docs/复刻总清单.md) 算，舵机单价以你到手价填。

## 10. 故障排查速查表

| 症状 | 最可能原因 | 动作 |
|---|---|---|
| 课 1 PING 无应答 | 电压不对（不是 12V）/ 线序反 / 波特率不是 1M | 量母线电压 → 核对 1=GND 2=Vcc 3=Signal → `--baud` 试 115200 |
| 读到全是 0xFF | TX/RX 没接到单总线 / 共地缺失 | 查转接板半双工端子；万用表量 GND 连通 |
| 写指令舵机动但读回来的位置不动 | 没开扭矩（40 号）或行程限制（9/11）卡住 | 课 3 前先读 40 和 9/11 |
| 12V 一上就"假死" | 14/15 号电压窗出厂值低于 12V → 过压保护 | 课 1 快照看 14/15，按要求放开 |
| 拷机丢包 | USB 串口延迟 / 线太长 / 共地噪声 | 降波特率对照；换短 PH1.25 线；加粗共地 |
| IMU 读数跳变 | 接线虚焊 / 地址错（0x6A vs 0x6B）/ 总线上拉缺失 | `i2cdetect` 稳定见地址；加 4.7k 上拉 |
| 摄像头 /dev/video 找不到 | FPC 插反 / 排线过长 / 设备树没开 | 翻面重插；换短排线；查 Armbian `armbian-config` |
| `policy load` 被拒 | ONNX 维度不对或 manifest 强制字段不符 | `inspect_onnx.py` 验 61/14；对 manifest schema |
| 吊装时某关节狂抖 | 该关节方向/零位与训练不一致 | 回阶段 A 的标定记录，核对方向位 |
