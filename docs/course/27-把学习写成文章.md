# 第 27 课 · 把学习写成文章:输出倒逼输入

> **这一课解决什么问题**:学了 27 课,怎么证明你真的学会?写出来。这一课给你一个固定的六段文章结构、一套选题方法(选题不是想出来的,是长出来的)和发布渠道建议。
>
> **前置**:做过任意一次实验(跑通 [第 05 课](05-第一次训练-冒烟测试.md) 即可)。素材在 `docs/microduck-30day/articles/`。

---

## 1. 为什么公开写作

两个理由,工作区里都有现成证据:

- **费曼式自检**。第 00 课立过规矩:"能讲出来才算学懂"。写作就是讲给不认识的人听——读者没法追问你,所以每一步都得自己先接住。写不下去的地方,就是你没学懂的地方。
- **踩坑记录让别人绕坑**。`microduck-replica/构建日志.md` 的"踩过的坑"一节开头写着:这一节是整份日志最有价值的部分——**别人可以不重复踩**。你写的每一篇排错文章,都可能替一个陌生人省下一整晚。

**所以呢**:写作不是"学成之后"的事,而是学习本身的最后一道工序——没有输出,闭环就没关上。

## 2. 固定文章结构(六段)

`docs/microduck-30day/articles/editorial-calendar.md` 规定每篇固定结构:**问题、源码证据、实验命令、结果证据、结论、未解决问题**。对照模板 `article-template.md` 和已成文范例 `day-01-5-iteration-smoke-test.md`,每段的要求:

1. **问题**:今天解决什么,边界在哪(2–3 段);
2. **源码/文档证据**:文件、行号、关键对象/函数、我的理解;
3. **实验假设**:一句填空——"如果我改变__,那么__应该变化,因为__";
4. **实验命令**:完整可复制,读者能原样跑;
5. **结果证据**:曲线/截图/视频,以及结果分析:哪些指标改善、哪些没改善、有没有替代解释;
6. **结论 + 下一步**:一句话区分已验证、推测、待验证;下一步只安排**一个**最小实验,不同时改多个变量。

看范例怎么写"诚实的结论":第 1 天文章里,`mean_reward` 从 -0.0614 升到 0.0950,是积极信号但**不是充分条件**;`fell_over` 仍接近 1.0。所以正确结论是"训练链路通过",而不是"鸭子学会走路"——两个结论必须分开。六段结构的价值正在于此:它逼你把"链路通了"和"效果好了"写进不同的句子里,不给自我感动留缝。

## 3. 选题不是想出来的,是长出来的

`docs/microduck-30day/README.md` 定义了每天的小闭环:

```text
读一小段源码 → 提出一个假设 → 跑一个小实验 → 保存证据 → 写一段结论
```

30 个选题就是 30 个小闭环的自然产物。看日历标题就知道:第 1 天《5 次迭代能不能证明训练环境可用?》来自冒烟测试;第 8 天《61 维 observation 是怎么拼出来的?》来自读观测代码;第 29 天《给机器人加上小智语音控制》来自第 23 课的 MCP 设计。**没有一篇是凭空"想选题"想出来的——都是当天真的做了、真的卡了、真的验证了。**

## 4. 你的第一个选题怎么挑

三条筛选,满足任意两条就写:

- 最近两周你真的卡住过、又真的解决了(证据已在手——比如构建日志里那个 `IndexError` 和 `CUDA_VISIBLE_DEVICES=""` 的解法);
- 你当时能搜到的中文资料很少(踩坑价值高);
- 结论里有可复制的命令或数字(别人能验证)。

## 5. 发布渠道建议

- **博客**:自己完全掌控,适合长文和代码块,建议作为母本;
- **公众号**:选题日历的栏目《从零复刻一只会走路的小鸭子》就是为它设计的,适合连载和传播;
- **GitHub**:把文章和实验记录放同一个仓库,读者可以复跑——"文章 + `experiment-log.csv`"是最有说服力的组合。

先选一个渠道,用固定结构写满 5 篇,再考虑一稿多发。

## 动手练习(20 分钟)

用 `article-template.md` 写出你第一篇文章的骨架:标题 + 问题段 + 已有证据清单。缺证据的段落留空并标"待补"——这份空格清单,就是你下一个实验的说明书。

## 自查清单

- [ ] 我能背出六段结构,并说出结论段要区分哪三种状态
- [ ] 我能解释为什么选题从"每天的小闭环"里长出来
- [ ] 我已经有第一篇文章的骨架,且知道下一个实验补哪个证据
