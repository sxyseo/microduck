# 第 22 课 · 平价路线:树莓派 Zero 2 W 方案

> **这一课解决什么问题**:主线(官方 Rust 运行时 + Radxa Zero 3W)不是唯一的路。这一课看一条已验证的平价路线——树莓派 Zero 2 W + Python 运行时 + 现成镜像,并练习一次真正的选型决策。
>
> **前置**:[第 12 课](12-采购与预算.md)、[第 18 课](18-Radxa点亮.md)(知道主线长什么样,才有得比)。

---

## 1. 同一只鸭子,两条路线

`Microduck-build-tutorial/` 是一份完整的中文复刻教程(模块化分篇 + 视频教程),它选了和主线不同的配置:

| | **主线(本课程默认)** | **平价路线(本课)** |
|---|---|---|
| 主控 | Radxa Zero 3W(¥299,见 `microduck-replica/docs/物料清单-进度快照.md`) | Raspberry Pi Zero 2 W |
| 舵机控制 | 主控直连总线 | 另加一块 OpenRB-150,经 USB 转发 |
| 运行时 | 官方 Rust(50Hz × 15 舵机闭环) | Python(同为 50Hz 控制环) |
| 上手方式 | 刷 Armbian + provision 脚本 | **现成镜像** `microduck.img.xz`,刷卡即用 |
| 适合谁 | 跟官方主线、用 dev-push 工具链 | 预算紧、想先看到动、Python 熟悉 |

两条路线驱动同一批 XL330 舵机、加载同样的 ONNX 行走策略,走的都是"仿真训练 → 导出 → 真机部署"这条链——差别在工具,不在方法论。

## 2. 现成镜像意味着什么

平价路线发布了预构建镜像 `microduck.img.xz`,里面已经装好:Raspberry Pi OS Lite 64-bit、主机名 `microduck`、默认用户 `user`、部署目录 `~/microduck`、Python 虚拟环境、行走模型 `walk.onnx`,还有一个开机自启的无头手柄服务。

也就是说:刷卡时填好 Wi-Fi,开机等 1–3 分钟,`ping microduck.local` 通了,`ssh user@microduck.local`(默认密码 `password`,**登录后立刻改**)——不装任何环境,鸭子已经在手里了。以后换模型,把新的 `walk.onnx` 放进 `src/agents/` 再 `make sync` 即可。

这对初学者价值巨大:第 03 课装环境预算要 30–45 分钟,是因为那次我们在**学**环境;当你只想**先看到它动**时,现成镜像把"环境搭建"这个最大劝退点直接跳过了。先看到反馈,再回头补课,完全成立。

## 3. 这条路线的局限

四条局限要心里有数:

1. **性能**:Pi Zero 2 W 跑 50Hz 闭环够用,但余量小;与主线的算力对比工作区没有实测数据,**待验证**;
2. **与主线不同构**:部署目录、更新方式(`make sync`)、运维工具都和主线(Rust daemon、`dev-push.sh`、健康门)不同——方法论相通,命令不通用;
3. **舵机数**:当前行走代码用 14 只(双腿 10 + 头颈 4),嘴部 ID 15 可选、不参与行走;
4. **维护线**:主线跟官方仓库走;平价路线的教程与镜像由教程作者维护,更新节奏以该仓库 README 为准。

## 4. 适合谁,以及为什么两条路都值得

选平价路线,如果你:预算紧(它的 BOM 逐项列了物料,价格随渠道浮动,以实时采购价为准)、想这个周末就看到鸭子动、或者 Python 是你的第一语言。

但别把两条路线对立起来。方法层面它们教的完全一样:61→14 的部署契约、50Hz 闭环、上电安全清单、手柄映射、训练→导出→部署的完整链路。这门课真正要你带走的不是某条命令,而是这套方法——[第 24 课](24-迁移地图.md)会告诉你,它比任何一块板子都保值。
