# 解读 166 · CAD 软件入门

> **解读对象**:概念课 · 以 `microduck-replica-cad/README.md`(SolidWorks 源文件/装配说明书/组件图)为教材
> **需要的前置**:[解读 33](33-装配反推方法.md);见过任意一张三维图即可,零基础可读。

## STL 是结果,CAD 源文件是过程

上游公开的 47 个 STL 只是"形状的结果":能看、能打印,改不了尺寸,也没有装配关系。`microduck-replica-cad` 仓库补的正是缺的另一半——图纸作者**「机械行者Robo」**(小红书号 270594280 / 抖音号 1852366168,"人人可做机器人")依据上游公开 STL 重建出**可编辑的 SolidWorks 参数模型**:56 个源文件(16 个装配体 `.SLDASM` + 40 个零件 `.SLDPRT`,解压 340MB)、一份 21 页装配安装说明书 PDF、23 张组件图/爆炸图,按 CC BY-NC-SA 4.0(署名-非商业-相同方式共享)发布,转载须保留署名。

读这套图的基本功只有三个词:**零件**(单个件,如 `leg_腿部`)、**装配体**(零件按配合关系装在一起,如 `00-microduck装配体`)、**特征树**(组件图侧边"这个总成由哪些件组成"的清单——解读 36/38 全靠它读图)。

## 文件大小也是信息

16 个装配体的体积很能说明复杂度:`00-microduck装配体` 70.3MB(全机总装)、`10_头部总成` 22.2MB、`01_躯干主体` 20.5MB,而 `07_颈根` 只有 0.1MB。装配体越大,引用的零件与配合关系越多——头部总成是全系列特征树最长的一份,与它 189g、装着主控/HAT/摄像头的身份相符(解读 38)。

README 还顺带教了一课仓库管理:SolidWorks 是二进制格式,git 对它既不能 diff 也不能合并,"改三次图仓库就上 1GB,而且历史删不掉"——所以源文件放 Release 附件,仓库本体始终只有几 MB。

## 两处命名坑与一套软件观

照图采购前先读 README"两处命名要留意":`np_f970_NPF970电池` 沿用了上游文件名,实物是 **NP-F550**(主仓实测包围盒 70.8×38.6×20.6mm;真 F970 厚约 60mm、约 300g,"买错装不进去,还吃掉整机预算的三分之一");`pcb__raspberry_pi_zero_2_w` 同样是占位命名,实机主控是 **Radxa Zero 3W**。文件名是遗产,以实测与 BOM 为准。

软件观(通用经验):SolidWorks 是商业软件,`.SLDPRT/.SLDASM` 是其私有格式,打开源文件需要相应 CAD;若只想看形状,STL 用 FreeCAD / Fusion 360 / Blender 都能开(主仓 README 原话);23 张组件图 PNG 和说明书 PDF 则零门槛。从哪一档入门都行,别让"没有软件"挡住看图。

## 你带走的收获

- STL 不可编辑,CAD 源文件才带设计意图:这个仓库把"过程"补齐了。
- 零件/装配体/特征树三个词,够你开始读任何一张组件图。
- 文件体积是装配复杂度的旁证:头部总成 22.2MB 不是白大的。
- 上游命名会骗人:np_f970 实为 F550、Zero2W 实为 Radxa——以实测与 BOM 为准。
- 二进制大文件别塞 git,发 Release 是图纸仓库的正确姿势。
