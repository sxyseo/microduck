# 解读 90 · buck 降压:5V 逻辑从哪来

> **解读对象**:`microduck-replica/docs/硬件方案逆向.md` §四(按官方 HAT 原理图 `dynamixel.kicad_sch` 核对)
> **需要的前置**:[解读 45](45-电源树.md)(整机电源树)、[解读 89](89-LDO线性稳压.md)(LDO 那条路)

如果说 LDO 是水管中间的减压阀(把多余压力变成热),buck 就是**高速开关的水泵**:开关每秒通断上百万次,配合一个电感(飞轮)储能释能,把电压"斩"出来——开关的占空比决定输出电压,能量几乎不浪费。官方 HAT 上那颗 buck 回答的问题是:主控吃的 5V 从哪来。

## 1. 电源链:六个符号从左到右

逆向文档按原理图符号的 X 坐标把这条链排出来(§四,勘误 2026-09-04):

```
+BATT(153) → C19(219) → U9 AP63205(302) → L4(392) → Q2(558) → U10 LM5050-1(568) → +5V(635)
```

从左到右就是电流方向。U9 = **AP63205**(降压变换器,2 A,开关频率 1.1 MHz),L4 = 6.8 µH 储能电感,C19 = 10 µF/63V 输入电容。buck 之后的 +5V 一路再经 Q2/U10(LM5050-1,理想二极管控制器,OR-ing + 配合 IO_06 的关机检测)送到三个去处:树莓派 40 针 J4、音频功放 PAM8406D、以及 U3 XC6206P182 再降到 +1V8 给音频 codec。

这次勘误本身就是教材:U10 曾被画在电池输入端当防反接,按 X 坐标重排才发现它在 buck **之后**——"读原理图先排电源链"是本仓用一次真实纠错换来的方法论。

## 2. 为什么这一路必须是 buck

算例:给 5 V 的负载供 1 A。用 LDO 从 8.4 V 降:效率 ≈ 5/8.4 ≈ 60%,耗散 (8.4−5)×1 = 3.4 W——小板上散不出去;用 buck(按九成效率量级估算):耗散不到 0.6 W。**压差越大、电流越大,buck 越是唯一现实解。** 树莓派功耗表(出自 `docs/执行器选型.md`):Pi 5 是 9–10 W、Pi 4B 是 6–7.6 W、Pi Zero 2W 是 1.5 W——这种瓦数用 LDO 降压等于在板上装暖气。

而 2 A 这颗 buck 也**带不动舵机**:单个 XL330 堵转约 1.5 A,15 个理论峰值 22.5 A(逆向文档 §四)。所以架构是"舵机吃电池原压 +BATT,buck 只喂逻辑"——不是偷懒,是分工。

## 3. 输入侧按高压设计

HAT 不是 Microduck 专用板(§四):输入电容 C19 用 63 V、C20 用 100 nF/50 V,原理图注释原文写着 "Power 24V 5A i.e. 7s/25c, from 21V to 29V"——Pollen 按通用机器人留足输入窗。给复刻者的余量是:换 3S(满 12.6 V)这条 buck 路不用动;要重算的反而是 LDO 那头([解读 89](89-LDO线性稳压.md))和舵机窗([解读 93](93-换电压改造清单.md))。AP63205 自身数据手册的输入范围本仓未记录,待验证。

## 你带走的收获

- buck = 高频开关 + 电感储能,效率与压差基本无关(九成量级);LDO = 可调电阻,多余压差全变热。
- 选择公式:电流大或压差大 → buck;几十 mA 的小负载 → LDO 便宜省事。
- 读电源链按符号坐标从源到载排一遍,保护器件的位置才不会张冠李戴。
- "带不动"要会算:稳压器电流预算对照负载最坏电流(堵转),不是额定。
- 模块化思维:HAT 的 buck 功能,复刻时可以整个换成一颗现成 UBEC(见[解读 91](91-UBEC选择.md))。
