# 解读 86 · 电池节数怎么定:1S/2S/3S 的数学

> **解读对象**:`docs/HL-2915路线全流程教程.md` §5.1(电池:选 3S)+ `microduck-replica/rl-series/scripts/hl2915_bench.py` 头注释「硬件前提」
> **需要的前置**:[解读 85](85-电压全景.md)(三代舵机窗口对照)· [解读 66](66-供电选型.md)(供电架构重设计)

"电池选几节"听起来是购物问题,其实是窗口匹配题。这篇把"节"和"窗口"两个概念从零讲清,再用仓库里三颗舵机的真实数字算一遍。

## 1. "S"就是串联节数:电压相加

锂电池单节标称 3.7V、充满 4.2V。模型圈用"S"数**串联**的节数——串联像老式手电筒把电池首尾相接:电压相加,容量不变。于是 2S = 两节串联,标称 7.4V、满电 8.4V;3S = 三节串联,标称 11.1V、满电 12.6V。仓库里的数字都能反推出单节:NP-F550 满电 8.4V ÷ 2 = 4.2V/节;教程 3S"满 12.6V、空 ~9.9V"÷ 3 = 满电 4.2V/节、放空 3.3V/节。同一块电池电压还随电量和负载漂移:NP-F550 带载时是 6.6–8.2V,不是铭牌上的 7.4V——**算窗口要用带载区间**,这是[解读 50](50-供电冲突.md) 的核心教训。

## 2. 窗口匹配:三种舵机,三种答案

选节数的判据一句话:**电池从满电到放空的整段电压,都要落在舵机窗口内**。拿三颗舵机各算一遍:

- **XL330(3.7–6.0V)vs 2S(带载 6.6–8.2V)**:整段高出上限。官方的选择是超压运行([解读 85](85-电压全景.md)),复刻者可以不照抄。
- **HD/HL-1910(4–8.4V)vs 2S**:整段落在窗内,"额定匹配"——但满电 8.4V 恰好等于上限,零余量(`硬件方案逆向.md` 的警告)。
- **HL-2915(9–14V)vs 2S**:整段低于下限。bench 脚本头注释原话:"HL-2915-C001 是 9-14V,**接 5V/2S 都不动**"——上电没反应不是舵机坏了,是电压根本没够到它的工作门槛。§5.1 的答案:**3S(满 12.6V、空 ~9.9V)正好全程落在窗内**,"这是换舵机路线最刚性的约束"。

台架阶段还不必买电池:12V 限流电源(限流先设 0.5A)就能覆盖 HL-2915 的全部台架课程——把电池这个变量留到整机阶段再引入。

## 3. 节数一变,牵一发动全身

节数不是孤立参数。教程 §5.2 的电力拓扑里,3S 之后保险丝台架用 5A、总装后按"实测走路峰值电流的 1.5 倍"换;UBEC 的输入规格要重写——HL-1910 路线采购单写的是"输入覆盖 **2S(6–8.4V)** 降压输出 5V≥3A",换 3S 这条验收规格就作废;舵机内部的保护窗(14/15 号寄存器,见[解读 88](88-过压保护.md))和软件里的电池窗(见[解读 87](87-代码里的电压.md))同步改。所以"换个电池"是**架构决策**:节数 → 母线电压 → 降压路径 → 保护阈值 → 软件常量,一条链全动。

## 你带走的收获

- S = 串联节数,电压相加:2S 满 8.4V,3S 满 12.6V,算窗口用带载区间。
- 判据是"全程落在窗口内":标称接近、平均值在窗内都不算数,要两端都在。
- "上电无反应"先对窗口:2S 带不动 9–14V 的 HL-2915 是物理事实,不是故障。
- 满电顶格 = 零余量:窗口上端要给满充留距离(HD-1910 的教训)。
- 节数联动保险丝、UBEC 规格、保护寄存器、软件电池窗——改节数是改架构。
